============================================================
1. PROJECT
============================================================

Project name:

AI Procurement & Vendor Intelligence Platform

The system is an AI-powered multi-agent procurement decision-support platform for businesses.

The platform helps procurement teams:

- create procurement requirements
- discover vendors
- research current external vendor/product information
- analyze supplier quotations
- check compliance
- assess vendor risk
- simulate negotiations
- run what-if procurement scenarios
- compare vendors
- generate explainable procurement recommendations
- obtain human approval

The project should be suitable for a college coursework demonstration while being architected like a realistic commercial B2B SaaS product.

============================================================
2. EXAMPLE USE CASE
============================================================

A procurement employee enters:

"We need 500 business laptops.

Requirements:
- Intel i7 or equivalent
- 16GB RAM
- 512GB SSD
- 3-year warranty
- delivery within 30 days
- total budget ₹50 lakh."

The system processes this request using multiple AI agents.

It should:

1. Understand the requirements.
2. Find suitable vendors.
3. Research current public vendor/product information.
4. Analyze supplier quotations.
5. Check compliance.
6. Assess vendor risk.
7. Calculate transparent vendor scores.
8. Simulate negotiation scenarios.
9. Simulate changing procurement constraints.
10. Produce a final procurement recommendation.
11. Allow a human procurement manager to approve/reject it.

============================================================
3. CORE DIFFERENTIATOR
============================================================

Do NOT build a generic:

"AI chatbot that recommends a vendor."

The main differentiator is:

PROCUREMENT NEGOTIATION + WHAT-IF SIMULATION.

The user must be able to ask:

- What if the budget drops from ₹50L to ₹45L?
- What if Vendor A is delayed by 10 days?
- What if the vendor increases its price by 8%?
- What if we negotiate a 5% discount?
- What if the warranty requirement changes from 3 years to 2 years?
- Which vendors remain compliant?
- Does the recommended vendor change?
- How does the overall procurement risk change?

The system should compare:

BASE CASE
vs
SIMULATED SCENARIO

Example:

BASE:

Vendor A
Price: ₹47L
Compliance: 100%
Delivery: 25 days
Overall Score: 93

SCENARIO:

Budget reduced to ₹45L

Vendor A:
Status: Non-compliant
New Score: 72

Vendor B:
Status: Compliant
New Score: 88

The UI must explain exactly WHY the result changed.

7. DATABASE VS WEB RESEARCH
============================================================

This distinction is critical.

PostgreSQL contains:

- historical vendor performance
- internal vendor information
- previous procurement records
- previous quotations
- historical quality
- historical delivery performance
- calculated scores
- stored web research evidence
- simulation history
- negotiation simulations
- agent execution logs

Web research provides:

- current public prices
- current product availability
- newly discovered vendors
- current public specifications
- current public certifications
- current external information

Do NOT replace PostgreSQL with web search.

Do NOT replace web search with PostgreSQL.

The two sources complement each other.

Example:

PostgreSQL:

Vendor A
- 42 previous orders
- 93% on-time delivery
- 96% historical quality
- internal rating: 4.6

Web:

Vendor A
- current public product price: ₹74,999
- current availability
- current product specifications

The system combines both sources.

Store the source URL and retrieval timestamp for web-derived information.

============================================================

Implement scoring entirely in Python.

Default weights:

Price: 30%
Compliance: 25%
Delivery: 20%
Reliability: 15%
Risk: 10%

overall_score =
    price_score * 0.30 +
    compliance_score * 0.25 +
    delivery_score * 0.20 +
    reliability_score * 0.15 +
    risk_score * 0.10

Make weights configurable.

Display every component.

The LLM can explain scores but cannot fabricate them.
